# ADR 0023: Scans that may have dropped data are partial

Status: Accepted

Findings are evaluated only against completed scans, and evaluation resolves open findings that are absent from the latest comparable scan. A scan that reports `complete` while a provider silently skipped a failed service, type, account, page, or describe would therefore resolve findings for resources that were never observed. Completeness must be an explicit claim by the provider, not the absence of a reported problem.

Every entry in `BatchScanResponse.Errors` is either a notice or an error. A notice leaves the scope complete. There are three kinds: `shared.UnsupportedTypeNotice` (the target has nothing of that type to list), `shared.AccessDeniedNotice` (the credential is not permitted to read something), and `shared.NotEnabledNotice` (a feature that would hold resources is turned off). Every other entry, including unprefixed entries from providers that predate the helpers, is an error: the scope was not fully observed. Providers report each failure that may have dropped resources with `shared.ServiceScanError` and keep the resources they did observe.

The executor marks a scope with any error as failed and the scan `partial`, which is persisted but never comparable and never resolves findings, matching ADR 0009's rule for incomplete envelopes. A scan is `failed` only when no scope answered at all. A streamed scan is complete only when the provider ends the stream with `io.EOF`; any other receive error is returned.

Permission gaps and disabled features are notices rather than errors because they are the credential's real scope, not a broken scan. Treating them as errors would leave most real scans permanently partial (a read-only role is routinely denied some resource types; most repositories have some security feature disabled), so findings would never resolve. The accepted cost is that a finding on a resource behind a denied type can be resolved even though the resource was not seen. To keep that visible, scans summarize coverage notices and errors as `coverage` and `incomplete` warnings. Failures that drop whole accounts or subscriptions, such as a member account whose role cannot be assumed, remain errors.
