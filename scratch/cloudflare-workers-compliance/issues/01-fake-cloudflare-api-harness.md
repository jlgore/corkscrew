# Forge-generated fake Cloudflare API

Status: complete
Depends on: —

Nobody publishes a seedable fake of Cloudflare's account REST API (checked 2026-10-22).
[mockflare](https://github.com/buurro/mockflare) covers only DNS, custom hostnames, and purge.
Prism serves spec examples and can't be seeded. So we generate our own fake from Cloudflare's
spec with [Forge](https://github.com/cloudflare/forge), Cloudflare's open-source OpenAPI
generation pipeline. Forge is early and its plugin interface will change. We accept that and
keep up with it (decided 2026-10-22).

## What was verified (2026-10-22)

- Forge isn't on npm (`@cloudflare/forge` returns 404). It builds from source with
  `cargo build --release --bin forge` in about 35 seconds. The repo pins Rust 1.99 in
  `rust-toolchain.toml`.
- Forge **can't parse** the Stainless spec that cloudflare-go is generated from
  (`unknown variant 'unknown' … at line 88884`).
- Forge **parses** `openapi.forge.json`, a release asset Cloudflare republishes in the
  `cloudflare/forge` repo several times a day (tags `openapi@<sha>`). It takes 0.6 seconds and
  covers 2,277 paths, including all 16 endpoints the provider calls today.
- The pins tried: Forge commit `91f52a40c746e8a2ac0271d8be0b7c82cdf28798`, spec release
  `openapi@536d02b4bd5629be5333aea4cf1024680abac1ef` (SHA-256
  `0bb99d95326da071cbb1072fc3273f2843581e31bb46ea394e820838e881be02`).

## Design

A Forge plugin (`forge:plugin@0.3.0`, TypeScript compiled to a wasm component with
`forge-plugin build` and jco) generates Go. The generated code is committed, so `go test` stays
offline and never needs Node, Rust, or Forge.

**Operation allowlist.** `tools/forge-fakecf/operations.txt` lists the `METHOD path` pairs the
provider calls. The plugin emits code only for those, plus the models they reach. Adding an SDK
call to the provider without adding its operation fails the tests, because an unrouted request
fails the test and names the method and path.

**Generated output** in `plugins/cloudflare-provider/internal/fakecf/` (header
`// Code generated by forge-fakecf. DO NOT EDIT.`):

- `routes_gen.go`: the route table, with the path pattern, path parameters, and the
  pagination style each operation uses (page/per_page or cursor), inferred from its query
  parameters.
- `schema_gen.go`: a validator for each response schema, generated from the Forge types. It
  checks required fields, scalar types, enums, array bounds, and discriminated unions (the
  Workers binding union, for example). It also records which fields Forge marks `sensitive`.
- `store_gen.go`: a typed fixture store keyed by operation and path parameters.

**Hand-written runtime** in the same package (not generated):

- `Server`: wraps `httptest.Server`. It answers list and get requests from the store, wraps
  results in the Cloudflare envelope (`success`, `errors`, `messages`, `result`, `result_info`),
  and pages them the way each operation's style requires.
- Corkscrew is read-only, so the fake only needs seed, list, and get. It emulates no create,
  update, or delete behavior. Any non-GET request fails the test.
- `Seed(op, pathParams, json)` validates every fixture against the generated schema at seed
  time. A fixture that doesn't match the spec fails the test that seeds it, so hand-written
  fixtures can't drift from the spec.
- It also validates incoming requests: path parameter shapes and unknown query parameters.
- Fault injection for each route: 403, 429 (with `Retry-After-Ms: 0`), 5xx, and a repeated page.

**Provider-side helpers** in `plugins/cloudflare-provider`: `newTestProvider(t, srv)` returns an
initialized `CloudflareProvider` that points at the fake, plus fixture builders in
`testdata/fakeapi/` for a baseline account (accounts, zones, worker scripts, routes, domains, R2,
KV, Queues, D1, DO namespaces, Secrets Store). Issues 03 to 05 add script settings and
subdomain.

## Regeneration

`make gen-cloudflare-fake`:

1. Clones Forge at the commit pinned in `tools/forge-fakecf/FORGE_COMMIT` and builds it.
2. Downloads the spec release pinned in `tools/forge-fakecf/SPEC_RELEASE` and checks it against
   `tools/forge-fakecf/openapi.sha256`.
3. Builds the plugin and runs `forge <spec> --target wasm://fakecf.wasm --out …`.
4. Runs `gofmt` on the output.

Keeping up with Forge: bump `FORGE_COMMIT`, `SPEC_RELEASE`, and the hash together in one commit,
regenerate, and fix the plugin when `forge.wit` changes. A CI job runs the generator and fails if
the regenerated output differs from what's committed.

## Spec mismatch is a signal

The fake validates against the Forge spec, but cloudflare-go is generated from the Stainless spec.
When a fixture is valid under the Forge spec and the SDK still can't parse it (or the reverse),
the test fails. Treat that as an SDK or spec disagreement to look into, not as a flaky test.
Record each case in the Comments section below.

## Acceptance

- `make gen-cloudflare-fake` reproduces the committed output from the pinned inputs.
- Characterization tests for every existing scanner (`accounts`, `zones`, `dns`, `workers`,
  `storage`, `data`) run through `ScanService` against the fake. Each asserts the resource types,
  IDs, and counts it returns, and that `Errors` is empty.
- A 403 on one account's KV list yields that account's other resources plus an error entry.
- A seeded fixture that breaks the schema (a missing required field, a wrong scalar type) fails
  with a message that names the operation and the JSON path.
- The ad hoc `httptest` servers in `paging_test.go` move onto the fake where that helps
  (the item-cap test uses its repeated-page fault).

## Comments

2026-10-22: Implemented on `feat/cloudflare-forge-fake`.

Where the build differs from the design above:

- **Generated data, not generated Go.** The plugin writes one file, `fakecf_gen.json`: 27
  operations and the 229 models they reach. Hand-written Go in `internal/fakecf` (`schema.go`,
  `server.go`) embeds and interprets it. That is far less generated code to review, and the
  validator is written once instead of once per schema.
- **The allowlist is `tools/forge-fakecf/operations.ts`.** Plugins can't read files, so the
  allowlist is a module compiled into the plugin.
- **Forge needs `--features wasm`** to run plugins. `gen.sh` builds it that way, along with the
  `@cloudflare/forge/plugin` library, which isn't on npm and is symlinked into
  `tools/forge-fakecf/node_modules`.
- **The Forge spec has no envelope.** Get operations are typed as the bare result, and lists as
  `{result, result_info}`. The fake adds `success`/`errors`/`messages`. It treats an operation
  as a list when its response has a required array `result`. It pages with `page` when the
  operation takes a `page` query param, with `cursor` when it takes `cursor`, and otherwise
  serves everything in one response. `result_info` gets only the fields its schema declares.
- **Unseeded requests:** a list answers empty. An object whose required fields are all arrays
  (R2's `{buckets}`) answers with them empty. Anything else is a 404.

Validation is strict: an object key the schema doesn't declare is an error unless the schema
allows extra keys. A union passes if any member matches (the discriminated member when there is
one). On failure it reports the closest member's errors.

Spec and SDK disagreements found so far:

- Durable Object objects list: the spec puts the next cursor at `result_info.cursor`, but the SDK
  (`CursorPaginationAfter`) reads `result_info.cursors.after`. The fake follows the spec, so the
  SDK never sees a second page. The baseline fixture has one object, so nothing depends on it
  yet. Durable Object objects are a candidate for capping or dropping anyway.
- R2 bucket `location` is lowercase (`wnam`) in both the spec and the SDK. My first fixture used
  `WNAM`, and seeding rejected it. That's the check doing its job, not a disagreement.

Verified: `gen.sh` reproduces the committed `fakecf_gen.json` byte for byte. `go test -race
./...` and `go vet` are clean in the plugin module. CI runs the fake's tests through the existing
`build-cloudflare-provider.yml` (`go test ./...`), and `cloudflare-fake-drift.yml` regenerates
and diffs.
